# 方案裁减表

架构审查只执行五层架构裂隙分析，按方案规模决定深度：

| 审查项 | 大方案 | 中方案 | 小方案 |
| --- | --- | --- | --- |
| 数据流 | ✓ | ✓ | ✓ |
| 失败模式 | ✓ | ✓ | ✓ |
| 状态切换 | ✓ | ✓ | — |
| 分层检查 | ✓ | ✓ | — |
| 运维隐患 | ✓ | — | — |

system_review 的六个一级维度始终全部出现：LLM、上下文工程、工具、约束、验证、纠正。

方案规模只决定每个一级维度的检查深度，不决定是否省略一级维度。成本、记忆、可靠性、评估等作为二级检查项，按以下关系挂载：

1. 成本挂到上下文工程和工具。
2. 记忆挂到上下文工程、验证和纠正。
3. 可靠性挂到工具、验证和纠正。
4. 评估挂到验证和纠正。

小方案也必须在六个一级维度下明确写出检查结果。没有发现问题时写检查对象和依据，材料不足时写缺失材料和后续验证方式。

架构审查、module_review 和 system_review 的职责边界以 CORE.md 为唯一事实来源。
