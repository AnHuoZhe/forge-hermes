# 系统调试模式

## 触发条件

forge-brief 的"加载文件"段包含本文件时执行。通常对应 retry_count >= 2 的场景。

## 流程

此模式替代正常 TDD 流程。按以下顺序执行，不跳过任何步骤：

1. **理解打回原因**：读 forge-brief 的 task brief，提取上一次打回的具体问题和修改意见。用自己的话复述一遍打回原因，确认理解正确。
2. **复现根因**：在修改任何代码前，先定位问题的根本原因。是接口不兼容？逻辑错误？还是设计层面的冲突？不修表面的症状——找到根。
3. **定位源头**：根因确定后，找到所有受影响的代码位置。不只修被打回的那个点，修所有同一根因导致的连带问题。
4. **修复并验证**：先让之前失败的测试通过，再跑全量测试。确保修复没有引入新问题。
5. **自问**："这个修复会不会在另一个场景下再炸？" 如果有疑虑，先处理疑虑再提交。

## 铁律

- 不允许直接跳到写代码——必须先走完前三步
- 如果根因是设计问题（不是实现问题），不硬修——在测试结果中标记 `design_issue: true`，让 forge 推进回退设计阶段
- 修复完成后回到正常 TDD 流程提交
