# 需求澄清方法论

## 流程

1. 从 `docs/forge-brief.md` 提取需求，多角度对撞刁难，记录结论：
   - 你真的要解决什么问题？
   - 去掉这个会怎样？
   - 有没有更简单的替代？
2. 竞品查漏：搜索 GitHub 同类项目 README 和 ProductHunt 同类产品描述，提取可核验的竞品功能列表，逐项问"竞品做了什么我们没做？"。网络不可用时明确记录未完成检索，不虚构竞品事实。
3. 先挖清需求，再用竞品列表对照；不让竞品功能替代用户问题本身。
4. 将核心功能写入 `docs/features.md`。每条功能单独一行，含功能名和一句话定义。
5. 用纸笔式场景走查验证功能覆盖：从核心用户触发、关键操作、成功结果到异常分支逐步走一遍；发现空白就回到功能清单补充或删改。
6. 将"需求洞察、竞品查漏、场景走查"简要写入 `docs/features.md` 的说明区，核心功能行保持一行一条。
7. 成功写入后更新状态：phase → design，追加 clarify 到 completed_phases。
